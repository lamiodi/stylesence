# Phase 1: display-only currency selection (₦ / $ / £) — NGN stays authoritative

Scope guard per your adjustments: **no payment changes** — cart, checkout, Paystack, orders, receipts, webhooks all remain 100% NGN. USD/GBP are display estimates with an explicit "charged in NGN" notice. No Stripe logic, no foreign order totals, no settlement changes, and — since nothing is stored per-product anymore — **no DB or Prisma changes at all this phase** (the safe versioned-migration work is deferred until a real price-book phase actually needs columns).

## Price model (single estimated rate — the mix banned in review is avoided)
- One estimated rate per currency, defined once in `fx.ts`: **USD = ₦÷1330, GBP = ÷1786** (best single-fit of the client sheet's own implied rates). Same rate for items, shipping, discounts, totals — internally consistent everywhere.
- Honest drift vs the client's quoted figures: Camille sets ($113/£84) and Ariellas ($120/£90) render exact; Àrẹ̀wà renders **$263/£196** vs quoted $264/£193 — inherent to one-rate display; rates live in one constants file, trivially tunable. The client's exact per-product price books (as real chargeable columns, `priceUsdCents`/`priceGbpPence`, variant-level if variants ever diverge) are explicitly a **later phase**, gated on confirming the merchant's live foreign-currency capability.
- Because the converted display replaces them, the five "International pricing: $… · £…" details bullets I added earlier today to `the-arewa-set`, `the-camille-skirt-set`, `the-camille-trouser-set`, `the-ariella-dress-short`, `the-ariella-dress-long` get removed (data-only row edit via script, no schema). Made-to-measure + garment-measurement bullets stay.
- No copy claims anything about Paystack's supported currencies anywhere; the checkout notice says only "orders are charged in Nigerian Naira (₦)".

## Detection & persistence (performance rules honored)
- Static ₦ first paint, always: **nothing waits on geo**. Detection runs once, client-side, after the page is visible (requestIdleCallback/setTimeout in `spa-shell.tsx`).
- **Cookie persistence** (`ss-currency` = NGN|USD|GBP, `ss-country` = country name; 1-year, SameSite=Lax): read synchronously at store init, so the mounted storefront renders the saved currency immediately (the shell's existing mount gate means no visible swap). localStorage mirror omitted (cookie is the single source, as chosen).
- `frontend/src/app/api/geo/route.ts`: returns `{ country }` from `x-vercel-ip-country` only (null locally), `Cache-Control: private, no-store`. Concrete app routes beat the after-files `/api/* → Render` rewrite; verified with curl during implementation (fallback: exclude via `beforeFiles` or rename the path). One fetch per visitor, ever; no FX API calls per product/page (all conversion is client math); no SSR reads of geo headers (pages stay CDN-cacheable); selector modal lazy-loads on open.
- Mapping: US→USD, GB→GBP, everyone else (incl. NG/GH/ZA/KE) → NGN until they choose.

## UI
